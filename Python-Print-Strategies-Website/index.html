Python-Print-Strategies

Basic python print statement strategies

What this is

I wrote print.py as a sequence of small, independent demonstrations, and I keep the order fixed because the order is the lesson. Each block shows one behaviour on its own. The script takes no input, defines no functions, and writes no file. It only prints.

This page follows the file recipe by recipe, in file order: a variable, a string, numbers, several values in one call, then the two same line forms, then comments. The last section is about comments themselves, so there the comments are the content, not notes about printing.

Run the whole book at once from the repo root:

python3 print.py

The recipes

1. Print a variable

data = "Fun secret variable"
print(data)

Produces: Fun secret variable

I start with a variable on purpose. Printing the variable prints the value it holds, not the name I gave it. That difference is the first thing a new reader trips on.

2. Print a string

print("Hello World")

Produces: Hello World

No variable, no setup. The string goes in, the string comes out, and print adds the newline at the end.

3. Print numbers

print(50)
print(1000)
print(3.142)

Produces: 50 1000 3.142

Two integers and a float, each on its own line because each call ends its own line. No quotes are needed, and none are printed.

4. Print several values in one call

print(50, 1000, 3.142, "Hello World") # Comma separation

Produces: 50 1000 3.142 Hello World

I pass four values in one call and let the commas do the work. Print puts exactly one space between values on its own, so I do not need spaces inside the strings. The note after the code is an end of line comment: the interpreter ignores it, the reader does not have to.

5. Stay on the same line with end=""

print("Hello", end="")
print("World")

Produces: HelloWorld

Here end="" replaces the newline with nothing, so the next print continues right where this one stopped and the two words run together. This pair only makes sense against the default it overrides: print ends the line unless I tell it not to.

6. Stay on the same line with end=" "

print("Hello", end=" ")
print("World")

Produces: Hello World

Same move, one character different. With end=" " I leave exactly one space instead of nothing, which is the only difference between this recipe and the one before it. Put side by side, the pair shows what end actually controls.

7. Comments, three ways

print(50)  # This line prints 50
print("Hello World")  # This line prints Hello World

# This is just a comment hanging out on its own!

# For multi-line comments, we must
# add the hashtag symbol
# each time

"""Docstrings are pretty cool
for writing longer comments
or notes about the code"""

Produces: 50 Hello World (the comments and the docstring block print nothing)

End of line comments explain a single line. Standalone comment lines stand on their own. A multi line comment in this file is just a hashtag on each line. The last block needs care: it looks like a comment, but it is really a string, a docstring used as a comment block. It only reads as documentation because it sits as a bare expression that nothing uses.
