Python-Print-Strategies

The teletype sheet, printed line by line in order. print.py is a teaching script that shows how the Python print call behaves. It asks for nothing, it reads no file, it only prints, and it runs with python3 print.py. Every row below is one thing the file prints, in the order the file prints it, checked against a fresh run: ten lines of output, exit code 0.

Same station, bigger number. The call does not change.

A decimal this time. Still one value, still one line.
T650 1000 3.142 Hello World
print(50, 1000, 3.142, "Hello World")
Four values in one call, landing on a single line with one space between each, because the commas in the call do that by themselves.

Rows seven and eight: the pair the file exists for

TRow 7

HelloWorld

End set to an empty string, so World runs straight onto Hello. No space, no new line.

TRow 8

print("Hello", end=" ")
print("World")

Hello World

The same pair with end set to one space, so the words land spaced properly. One character is the whole difference.

T950
Hello World
print(50)  # This line prints 50
print("Hello World")  # This line prints Hello World
The closing lines: the two values printed again, each with a comment after it explaining the line. The comments change nothing in the output.

Comments, as the file teaches them

A lone hash comment sits on its own line and the interpreter skips it:

# This is just a comment hanging out on its own!

Longer notes repeat the hash at the start of every line:

# For multi-line comments, we must
# add the hashtag symbol
# each time

And the triple quoted block at the end of the file is shown for what it is, a string sitting unused, not a true comment:

"""Docstrings are pretty cool
for writing longer comments
or notes about the code"""

The script contains no input, no functions, and no output file. The sheets in the visuals folder belong to the same repo.
